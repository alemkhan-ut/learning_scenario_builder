## Commands

The editor lives at `C:\Program Files\Unity\Hub\Editor\6000.3.21f1\Editor\Unity.exe`. Batch-mode commands fail if the project is already open in the Editor. When the Editor is running, use the Unity MCP tools (`mcp__unity-mcp__*`: console logs, script validation, scene/GameObject management) instead.

Run tests in batch mode (EditMode or PlayMode). Tests need their own `.asmdef` that references the Test Framework:

```powershell
& "C:\Program Files\Unity\Hub\Editor\6000.3.21f1\Editor\Unity.exe" -batchmode -nographics -projectPath . `
  -runTests -testPlatform EditMode -testResults Logs/TestResults.xml -logFile Logs/tests.log
```

- Run a single test or fixture: add `-testFilter "Namespace.ClassName.MethodName"` (regex supported; separate several with `;`).
- Builds: use the `unity-build` skill. It builds with the current build settings into a new timestamped folder.
- Debugging: VS Code's "Attach to Unity" launch config (`vstuc`). The solution file is `learning_scenario_builder.slnx`. `.csproj`/`.slnx` files are generated by Unity and gitignored.
